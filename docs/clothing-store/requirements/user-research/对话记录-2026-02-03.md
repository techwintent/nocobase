### 2. 数据录入困境 ⭐⭐⭐

**问题描述**：
- ✅ 软件有数据功能
- ❌ **没有时间精力仔细录入**
- ❌ 客户详细身形信息、产品衣长等 → 录入不全
- ❌ 熟悉客户备注在微信，但很多客户"不知道谁是谁"

**核心矛盾**：
```
实体店的现实 ≠ 电商的标准化

电商：可以花时间详细录入每个商品的尺寸、材质、版型
实体店：节奏快，没时间录那么细

结果：有 AI 但没有高质量数据 → AI 无法发挥作用
```

**场景还原**：
1. 客户来店里，想聊天的会聊几句 → 能备注
2. 有些客户有防备心或时间赶 → 没时间备注
3. 最近加的微信 → 都不知道谁是谁

**她的真实需求**：
- ✅ 保存客户照片（识别客户）
- ✅ AI 整合模糊信息（不需要录入太详细）
- ✅ **如何将获取的信息直接备注到软件**

### 3. 核心痛点：组货和搭配能力 ⭐⭐⭐

**原话**：
> "我们现在很需要的还有**组货和搭配能力**，这个其实可以作为同一个点。**拿货的时候如何搭配，卖货通用**。"

**理解**：
- "组货" = 进货时的搭配（批发场景）
- "搭配" = 卖货时的搭配（零售场景）
- **两者是同一个能力的不同应用场景**

**场景1：进货（批发场景）**
```
去批发市场拿货时：
- 问题：不知道这件上衣配什么裤子好卖
- 需求：AI 告诉我这件上衣应该配哪几条裤子一起拿
- 目的：拿回来的货能形成完整搭配，好卖
```

**场景2：卖货（零售场景）**
```
客户来店里买衣服时：
- 问题：不知道推荐什么搭配
- 需求：AI 告诉我这件衣服配什么最好卖
- 目的：提升连带率、客单价
```

### 启示 2：组货搭配是核心功能 ⭐⭐⭐

**南瓜的原话验证了我们的方向**：
> "我们现在很需要的还有**组货和搭配能力**"

**但我们理解错了场景**：

**我们原来的理解**：
- 组货 = 进货决策（进什么）
- 搭配 = 卖货时推荐（怎么搭）

**南瓜的实际需求**：
- 组货 = **进货时的搭配**（这件上衣配什么裤子一起拿）
- 搭配 = **卖货时的搭配**（客户买上衣时推荐什么）
- **两者是一回事，只是场景不同**

**实现思路**：

#### 核心算法：搭配推荐引擎
```python
def recommend_match(product_id, context='selling'):
    """
    推荐搭配商品
    
    Args:
        product_id: 当前商品ID
        context: 场景 ('buying' 进货 | 'selling' 卖货)
    
    Returns:
        推荐搭配列表
    """
    # 1. 基于历史销售数据的连带率分析
    co_purchase_data = get_co_purchase_rate(product_id)
    
    # 2. 基于商品属性的规则匹配
    #    例如：碎花连衣裙 → 推荐纯色单品
    attribute_match = get_attribute_match(product_id)
    
    # 3. 综合排序
    recommendations = merge_and_rank(
        co_purchase_data,  # 权重 70%（数据驱动）
        attribute_match     # 权重 30%（规则驱动）
    )
    
    # 4. 根据场景调整
    if context == 'buying':
        # 进货场景：考虑库存，避免重复
        recommendations = filter_by_stock(recommendations)
    elif context == 'selling':
        # 卖货场景：优先推荐库存充足的
        recommendations = prioritize_in_stock(recommendations)
    
    return recommendations
```

### 启示 3：简易易用是核心竞争力 ⭐⭐⭐

**南瓜的痛点**：
> "很多功能都有，就是嫌繁琐，或者摸索不透，导致很多功能有用却没用上"

**问题根源**：
```
商陆花/笑铺日记功能太多（十多年累积）
→ 界面复杂、路径深
→ 好功能藏得深、不知道在哪
→ 即使知道在哪，也懒得用（因为繁琐）
```

**Wintent 的设计原则**：

#### 1. 主动推送 > 被动查询
```
❌ 错误：提供"搭配推荐"功能，让用户自己去点
✅ 正确：当用户添加商品到购物车/进货单，自动弹出搭配建议

❌ 错误：提供"客户分析"功能，让用户自己去看
✅ 正确：每天早上推送"今日建议"：15位客户预计今天来店
```

#### 2. 一步到位 > 多步操作
```
❌ 错误：查看进货建议 → 选择商品 → 查看详情 → 生成建议
✅ 正确：首页直接显示"3款商品需补货"，点击立即下单

❌ 错误：客户管理 → 筛选 → 沉睡客户 → 查看列表
✅ 正确：首页显示"35位沉睡客户待回访"，点击一键群发
```

#### 3. 自然语言 > 专业术语
```
❌ 错误："RFM 模型分析"、"库存周转率"、"连带率"
✅ 正确："哪些客户该回访了"、"哪些货卖得慢"、"这件衣服配什么好卖"
```

#### 4. 渐进式复杂度
```
Level 1（新手）：只看首页的"今日建议"
Level 2（进阶）：点进去看详细数据和分析
Level 3（高级）：自定义规则和参数

默认界面极简，高级功能可选展开
```
